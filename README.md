## 📌 Project Overview

This repository showcases my hands-on experience in **Manual Software Testing** across the SauceDemo e-commerce demo website and [Himal Innovative Development & Research Pvt. Ltd. (HIDR)](https://hidr.com.np/).

The objective of this project was to evaluate website functionality, usability, responsiveness, and compatibility while practicing the Software Testing Life Cycle (STLC), preparing QA documentation, executing test cases, identifying defects, and reporting bugs.

I worked on test planning, test scenario and test case design, test execution, and defect reporting using tools such as Google Sheets, Google Docs, Jira, and Trello.

## 🧪 Testing Types Performed

### 1. Functional Testing
- Validated application features and user workflows.
- Checked input fields, buttons, links, navigation, and form validations.
- Performed positive and negative testing.
- Verified actual results against expected results.

### 2. Non-Functional Testing
- Evaluated usability and ease of navigation.
- Observed application responsiveness and overall user experience.
- Checked visual consistency and general application behavior.
- Reviewed page loading behavior and performance-related observations.

### 3. UI (User Interface) Testing
- Checked layout, alignment, spacing, and text visibility.
- Verified buttons, links, forms, and other interactive elements.
- Identified visual inconsistencies and UI defects.
- Evaluated the consistency of page elements.

### 4. Responsiveness Testing
- Checked website layouts at different screen sizes.
- Verified the visibility and accessibility of UI elements on different viewport sizes.
- Observed text wrapping, alignment, and horizontal scrolling issues.
- Evaluated whether the website layout adapted appropriately to different screen dimensions.

### 5. Compatibility Testing
- Checked website behavior across different browser and device configurations.
- Evaluated the rendering and functionality of website elements.
- Observed differences in layout and behavior across supported environments.

### 6. Cross-Browser Testing
- Tested website behavior across multiple browsers.
- Compared UI rendering, navigation, and functionality between browsers.
- Identified browser-specific inconsistencies where observed.

### 7. Regression Testing
- Re-executed relevant test cases after changes or fixes, where applicable.
- Verified that previously working functionality continued to behave as expected.
- Checked for unintended effects on existing features.

### 8. Smoke Testing
- Checked essential application functionality before deeper testing.
- Verified that critical pages and workflows were accessible and operational.

### 9. Positive and Negative Testing
- Validated expected behavior using valid inputs.
- Tested invalid inputs and unexpected user actions.
- Checked validation messages and error handling.

## 📝 Testing Activities & Responsibilities

### Test Planning
- Prepared a test plan document outlining testing objectives, scope, approach, and activities.
- Identified features and functionalities to be tested.
- Organized the testing process and documentation.

### Test Scenario & Test Case Design
- Created test scenarios covering important application workflows.
- Designed test cases with preconditions, steps, test data, and expected results.
- Included positive and negative scenarios.
- Reviewed test cases for clarity, coverage, and unnecessary duplication.

### Test Execution
- Executed test cases manually.
- Compared actual results against expected results.
- Recorded test execution status, including Pass and Fail.
- Documented observations and collected evidence for identified issues.

### Bug Reporting & Defect Tracking
- Identified and documented defects discovered during testing.
- Prepared structured bug reports containing:
  - Bug ID and summary
  - Preconditions and test environment
  - Steps to reproduce
  - Expected result
  - Actual result
  - Severity and priority, where applicable
  - Screenshots or supporting evidence
- Used Jira and Trello for bug reporting, issue organization, and tracking.

## 🔄 Manual Testing Workflow

1. Understand the application and its functionality.
2. Define the testing scope and prepare the test plan.
3. Create test scenarios and test cases.
4. Execute test cases manually.
5. Compare actual results with expected results.
6. Record execution results and collect evidence.
7. Report defects using Jira or Trello.
8. Track issues and document the testing outcome.
